# Canonical data: monsters, drops and breakables (Maple Island)

Authority: **MeowDB MS Classic** (`https://meowdb.com/msclassic`). It documents *MapleStory Classic World* (Nexon, 2026)
and uses its own ids, which are not GMS ids. Nothing in these files comes from memory or another wiki. Since Iteration
Three the **drop records** name a second and a third authority per property (contract C1, decisions D3-3 to D3-9):
Hidden Street for monster drop membership and most meso amounts, KuroDB for drop and meso chances, each read from a
dated hand-read capture under `tools/*/captures/`. See [Drops](#drops-schema-v2-records).

Generated by `node tools/meowdb/extract_monsters.mjs`. The script reads the cache and the dated captures (never the
network), is deterministic, and re-running it reproduces every file byte for byte. The drop records are built by
`tools/sources/drops_merge.mjs`, which the extractor calls.

| Output | Contents |
|---|---|
| `game/data/canonical/monsters/<id>.json` | One file per monster: `1`, `2`, `3`, `4`, `5`, `9` |
| `game/data/canonical/drops/<owner_id>.json` | One schema v2 drop record per monster (`1`...`9`) and per breakable (`0000001`) |
| `game/data/canonical/breakables/<id>.json` | One file per breakable: `0000001` (Wooden Box) |

## TL;DR for the game programmer

1. **Six monsters** live on the 25 Maple Island maps: 1 Tutorial Jr. Sentinel, 2 Snail, 3 Blue Snail, 4 Shroom,
   5 Red Snail, 9 Orange Mushroom. There is also **one breakable**: `0000001` Wooden Box. No other monster, reactor
   or breakable appears on those maps.
2. Base stats (level, HP, MP, EXP, P.DMG, defences, ACC, AVOID, speed, KB) are **canonical**. Use them unchanged.
3. **Drops come from three sources, one per property** (`drops/<id>.json`, schema v2, contract C1). Membership (what
   can drop): Hidden Street's per-monster lists (D3-6); MeowDB's list for the Wooden Box (D3-7). Chance: KuroDB, only
   for members its page also lists (D3-3). A member without a KuroDB chance or a local item stays in the record,
   unresolved, and never rolls. A KuroDB-only item is never added. See [Drops](#drops-schema-v2-records).
4. **Meso amounts:** MeowDB's one player report (Snail: 2 mesos per kill), else Hidden Street (Blue Snail 4, Shroom 4-6,
   Red Snail 8-12, Orange Mushroom 9-13). **Meso chance:** KuroDB 40% for those five. The Tutorial Jr. Sentinel and the
   Wooden Box drop no mesos (D3-5).
5. Nothing outside the drop records may supply a chance, quantity or meso amount. `game/data/misostory/drop_rates.json`
   only documents the runtime's interpretations (uniform meso amount, the quest-gate rule).
6. Touch damage: use `physical_damage` (P.DMG) with the damage-taken formula (formulas domain). The
   `touch_damage_estimate_at_0_wdef` range is MeowDB's own estimate for display. It is not a stat. Orange Mushroom
   proves this: its estimate starts at 18 while P.DMG is 17.
7. Respawn: on Maple Island every spawn point is a **wave** point (`respawn_kind: "wave"`). MeowDB models these as a
   global 7.56 s server tick plus a 5 s per-point cooldown; the page displays this as "~7.5s". Spawn positions are not
   here. They belong to the maps domain (map page `spawns[]`).
8. **`mob_rate` has a disputed meaning inside MeowDB.** The map pages and the monster-page tooltip call it a multiplier
   on live monsters; the glossary says there is no map-wide multiplier. The number is stored verbatim and nothing is
   multiplied. Whether to apply it is a design decision (see [Discrepancies](#discrepancies)).
9. **Monster knockback: a threshold and a stagger time.** `knockback_threshold_damage` (KB) and `stagger_ms` (600 ms for
   all six: "STAGGER 0.6 seconds. How long the mob is staggered for when knocked back.", from the live pages read on
   2026-10-05; the 2026-10-04 cache predates the field) are what MeowDB gives. Push distance is not published. The
   "Knockback Airtime" model on `/formulas/damage-taken` is for the **player** being hit, not for monsters.

### `spawns[]` rows

| Field | Meaning |
|---|---|
| `map_id`, `map_name`, `street_name` | 9-digit MeowDB map id and names |
| `maple_island` | `true` if the map is one of the 25 Maple Island maps |
| `count` | Spawn points for this monster on the map |
| `map_total_spawns` | All spawn points on the map (every species) |
| `share_pct` | **Derived**: `round(100 * count / map_total_spawns)`. Matches the page's "Share" |
| `map_mob_type_count` | Number of monster species on the map (page "Types") |
| `mob_rate` | Page "Mob Rate" (e.g. 1.3), stored verbatim. **Its meaning is disputed within MeowDB.** The map pages and the monster-page tooltip say it "multiplies how many monsters this map keeps alive at once" ("our best reading from closed-beta play"; their own spawn figures do not apply it). The glossary says live capacity is spawn points scaled by party size, with "no separate map-wide multiplier". Every monster file records the three texts in `discrepancies` (`spawns[].mob_rate (meaning)`) |
| `wave_spawn_count`, `timed_spawn_count` | Wave points vs timed points. `timed_spawn_count = count - wave_spawn_count` (derived, same as the page's client code) |
| `respawn_kind` | `wave` (all wave), `timed` (all timed) or `mixed` |
| `respawn_min_s`, `respawn_max_s` | Respawn of the **timed** points in seconds. `0` for wave points. Example: Orange Mushroom in An Empty House (`010001002`), 1800 s ("about every 30 min") |

Respawn model (from `/formulas/spawns`, MeowDB's model): global respawn tick = 7.56 s. A wave point waits a 5 s cooldown
after its mob dies, then the mob returns on the first tick after that. Capacity scales with the number of players:
`floor(spawn_points * min(1, 0.75 + 0.05 * (players - 1)))`. These are map/formula rules. They are summarised here
only so the `wave` label makes sense.

### Where each field comes from

The detail page is canonical for everything it shows. The raw table chunk is used only for `knockback_threshold_damage`,
`flags.boss/undead/auto_aggressive/tags`, `hp_recovery`, `mp_recovery`, `revives_into`, `element.raw`, Orange
Mushroom's `speed`, and to turn the page's "—" into 0. For every field the page shows, the extractor **asserts** that
the raw table agrees (level, HP, MP, EXP, P.DMG, ACC, M.DMG/P.DEF/M.DEF/AVOID, speed, non-aggressive). Any disagreement
would be written to `discrepancies`. There are none for stat values. The only entry in each monster file's
`discrepancies` is the `mob_rate` meaning conflict (see [Discrepancies](#discrepancies)). Each such field has a `field_sources` entry naming its URL and
retrieval time.

## Drops: schema v2 records

`drops/<owner_id>.json` is a **schema v2 drop record** (contract C1 in
[`../runtime/ITERATION_THREE_CONTRACTS.md`](../runtime/ITERATION_THREE_CONTRACTS.md)). It keeps *what can drop* and
*how often* apart, each value with its own source (decisions D3-3 to D3-9 in [`../ITERATION_LOG.md`](../ITERATION_LOG.md)):

| Property | Monsters 1 2 3 4 5 9 | Wooden Box 0000001 |
|---|---|---|
| Membership (what can drop) | Hidden Street "Before Chaos" drop lists, `tools/hiddenstreet/captures/monsters.json` (D3-6). Post-Big-Bang GMS v0.96, a different game version; used by the owner's decision | MeowDB's live breakable page, `tools/meowdb/captures/breakable_0000001.txt` (Hidden Street has no breakables, D3-7) |
| Chance | KuroDB monster page, `tools/kurodb/captures/<kuro id>.json`: `"<p>% base"` = p / 100 | KuroDB reactor 2001 rows on the members' item pages, `tools/kurodb/captures/reactor_2001_items.json`: `"Chance value N"` = 1 / N, an interpretation (D3-7) |
| Quantity | KuroDB `"Qty n"` | Not published; 1 per roll, a labelled MisoStory adaptation (`quantity.adaptation`, `verified: false`) |
| Meso amount | MeowDB's player report (Snail, live page) else Hidden Street (D3-5) | none |
| Meso chance | KuroDB `"40% base \| Meso drop"`; no KuroDB meso row = no mesos (Tutorial Jr. Sentinel) | none |

The three sites use unrelated item ids (KuroDB 4000019 is Snail Shell, MeowDB's `game_item_id` 4000001 is Snail
Shell, KuroDB 4000001 is Orange Mushroom Cap), so the join is **by name**, through the reviewed crosswalk
[`tools/sources/crosswalk/drop_items.json`](../../tools/sources/crosswalk/README.md). Each row says how it matched
(`exact`, `normalized`, `alias_with_evidence`, `none`) and why. A KuroDB row that no member matches is written to
`excluded_kuro_only`: **KuroDB never adds an item**. A member without a KuroDB chance, or without a local MeowDB item,
stays in `entries` with `chance_state: "unresolved"` or `item_id: null`, never rolls, is listed in the record's `gaps`,
and the data validator lists it as a `drop_unresolved` warning.

**Quest gate (C1 rule, D3-9, `verified: false`).** An entry is gated only when its membership source or MeowDB's item
subtype marks it a quest item **and** a Maple Island quest objective asks for it; the gate is that quest. It rolls
only while the quest is in progress. KuroDB's `"| Quest N"` flag (its own quest ids) is kept as
`kuro_quest_condition`, corroboration only. Result: Old Wooden Board and Rusty Screw are gated to Pio's quest 1012;
Jr. Sentinel Shellpiece (MeowDB subtype "Monster Drop") is not, although KuroDB flags it "Quest 1035".

### MeowDB's own drop data (reference)

MeowDB publishes, per monster, a community-voted list of items "players have personally seen drop in Classic World"
(with up/down votes) and a read-only "MSEA reference drops" list ("historical reference only"), and player meso reports.
It publishes no drop chance, no quantity and no meso drop chance. The records keep its lists in `meowdb_reference`

## Gaps (MeowDB lacks these)

- Per-item drop chance, drop quantities, meso formula, and meso drop chance, for all monsters and the Wooden Box. The
  drop records take chances and quantities from KuroDB and missing meso amounts from Hidden Street (D3-3 to D3-6);
  what those sources leave open is listed in each record's `gaps` (see [Drops](#drops-schema-v2-records)).
- Meso reports for monsters 1, 3, 4, 5, 9 (zero reports, also on the live pages). Snail has a single report.
- The meaning of `trustedCount` in the meso API.
- Monster attacks other than touch: the pages list no attack entries (skills, ranged or magic attacks) for these six.
  Touch-damage rules belong to the formulas domain (`/formulas/damage-taken`).
- `kb`, boss/undead tags, HP/MP recovery and revives are not shown on the detail pages. They come from MeowDB's own
  simulator data chunk (still MeowDB, recorded in `field_sources`).
- Orange Mushroom's numeric speed is not on its page ("Normal" only). The value 0 comes from the same chunk.
- `category_label` ("Standard") is not defined anywhere we read.
- Mai's Final Training (quest 1010) shows no "Lv N+" on the Orange Mushroom page, so `quests[].min_level` is `null`
  there. The quest page (quests domain, `quests/1010.json`) gives `min_level: 0`. Read quest requirements from the
  quests domain, not from monster files. The monster file records this as a gap.
- **Monster knockback:** MeowDB gives the KB threshold and, on the live pages, the stagger time (`stagger_ms`, 600).
  How far or how high a monster is pushed is not published. `/formulas/damage-taken`'s "Knockback Airtime" (under
  "After You Get Hit") is the player's knockback. It must not be reused as monster data without labelling it a
  MisoStory adaptation.
- **Peace monster touch damage (Tutorial Jr. Sentinel):** the same page says "Peace" ("Non-aggressive, won't attack
  unless provoked"; analysis: "Safe to walk past.") and also shows a 21x36 touch zone, Touch DMG 1-1 (Base 1) and the
  generic text "The touch zone deals contact damage when you walk into it." MeowDB does not say whether walking into a
  Peace monster's touch zone hurts the player. Recorded as a gap in `monsters/1.json`.
- Wooden Box: no HP model beyond "4 basic attacks"; whether skills or damage change the count is not stated; whether
  quest-item drops (Rusty Screw, Old Wooden Board) are quest-gated is not stated (the records gate them by the C1 rule,
  D3-9, `verified: false`); nothing about meso drops.
- MeowDB does not say how a monster's "Jumps between floors" movement decides when to jump.
- Animation frame-by-frame delays are not published, only total clip length.

Cross-checks that **passed** (the extractor re-runs them every time): monster-page spawn counts, wave counts, mob

that monster's page. Raw-table stats equal page stats. "Map Locations (n)" headers equal the list lengths. MSEA
"n items" headers equal the parsed counts. Wooden Box placement totals (19) and drop counts (4) match the /breakables

An independent verification pass (2026-10-04) checked the same data by a different route and found no value errors.
It compared every stat, animation, quest, change-history and Map Locations row (including Victoria Island rows,

## Notes for using the data correctly

- **Ids are MeowDB ids.** Monsters `"1"`...`"9"`, items `"348"`, quests `"1006"`, maps `"000000040"`, breakables
  `"0000001"`. They are not GMS ids. `meowdb_icon_key` is not an id.
- **Coordinates** (breakable placements) are MapleStory px with y pointing down. Converting them to isometric 3D is
  MisoStory adaptation work. Do it in `data/misostory`.
- **Touch zone** is anchored to the bottom centre of the sprite. Scale it with whatever px-to-metre factor the
  MisoStory adaptation uses.
- **Non-aggressive** Tutorial Jr. Sentinel: MeowDB says "won't attack unless you hit it first. Safe to walk past." Its
  page *also* shows a touch zone (21x36), Touch DMG 1-1 and the same generic text as every monster: "The touch zone
  deals contact damage when you walk into it." MeowDB does not settle whether a Peace monster's touch zone hurts. That
  is a gap, not a fact. The other five have no "Peace" attribute and no `auto-agg` tag, and the touch-zone text applies
  to them without conflict.
- **Knockback:** KB 1 means any hit that deals 1 or more damage staggers them (glossary: "a mob with 500 KB needs 500+
  damage to stagger"), for `stagger_ms` (600 ms, the live pages' "STAGGER 0.6 seconds"). Push distance is not
  published. The "Knockback Airtime" model on `/formulas/damage-taken` is the **player's** knockback ("After You Get
  Hit"). Any monster push-back the game uses is a MisoStory adaptation and belongs outside `data/canonical`.
- **Names are verbatim.** MeowDB's raw map name for `010001020` is `"A Hill West of Henesys "` (trailing space) in the
  Blue Snail and Red Snail spawn rows. The extractor does not normalise names. Key on `map_id`.
- **Drops spawn at death**, not after the fade.
- **Drop chances come from KuroDB, membership from Hidden Street (MeowDB for the Wooden Box).** Join items by the
  record's `item_id`, never by a KuroDB or icon id. See [Drops](#drops-schema-v2-records).

## Implementation notes (extractor)

- Monster stats are rendered into the Next.js RSC tree, not shipped as JSON. The extractor parses every RSC row and
  walks the element tree, resolving `$L<hex>` refs. It treats rows that no parsed row references as roots, because
  `rsc()` output has no row `0` (the page root). This is not a bug in `lib.mjs`. It only means tree walkers must not
  assume row 0 exists. No `lib.mjs` bugs were found.
- The raw-table chunk URL is pinned (`782-bb5a5ee666dc6188.js`). If MeowDB redeploys and the hash changes, find the new
  chunk from `/avoidability-sim` and update `RAW_TABLE_CHUNK`.
- Client-side endpoints were found by reading the page JS chunks (`fetch(\`/msclassic/api/drops?monsterId=${t}\`)`,
  `.../mesos-reports?monsterId=`, `.../breakable-drops?breakableId=`).
- Quoted MeowDB prose (glossary "mob rate", the map pages' "About mob rate." paragraph, the Combat Details touch-zone
  text) is read structurally from the RSC tree with `Tree.rawText()`. That helper concatenates the untrimmed string
  tokens, so the quoted sentences keep MeowDB's own spacing. The `mob_rate` discrepancy is emitted only while both
  positions ("multiplier" and "no separate map-wide multiplier") are present in the cached pages. If MeowDB reconciles
  them, a `--refresh` run drops the entry instead of leaving it stale.
